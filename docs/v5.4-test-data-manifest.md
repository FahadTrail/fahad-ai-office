1. **Group P:** `continuity_handoffs`, `continuity_checkpoints`, `continuity_events`, `continuity_usage`, then `continuity_tasks`.

   `knowledge_items.job_id` is set to null by its foreign key.

7. **Audit:** one `events` row with `kind = test_data_cleanup`. It records the groups, the objective IDs, every count and the removed model cost.

## Fail-closed checks

The script stops and changes nothing in any of these cases:

**Options**
* `cleanup.apply = 'yes'` without an explicit `cleanup.groups`.
* An unknown group letter.
* A `cleanup.expect_jobs` value that differs from the selected count.

**Manifest**
* The lists inside the script differ from this manifest: 81 objectives, 28 evidence, `A3,B27,C37,D14`, 30 conversations, 2 Continuity tasks.

**Drift since the manifest**
* A selected objective changed: its timestamp, project, status, task count, run count, model attempts, tool runs, coding sessions or knowledge items.

**Activity**
* A selected objective or coding session was active in the last hour.
* A selected coding session holds a lease or is not in a terminal state.

**Dependencies**
* Any row outside the selection references a selected task, run, coding session or objective. This includes launch events in either direction.

**Conversations**
* A listed conversation holds an objective, coding session or artifact that is not selected.

**Certification project**
* It was renamed.
* It holds anything outside the selection: objectives, coding sessions, approvals, tool runs, model attempts, artifacts, conversations, coding-worker sessions or project memory.

**Continuity proof-of-concept tasks**
* A task changed key, status or child counts.
* A task holds a live lease.
* Another task's handoff uses one of its checkpoints.

Rows that an earlier approved run already removed are reported as "already removed" and skipped. If nothing is left in the chosen groups, the script stops.

## How to run (Fahad only)

Use a direct or session-pooler connection as `postgres`, or the Supabase SQL editor.

```sh
# 1. Preview. Changes nothing and prints every count:
psql "$DB_URL" -X -v ON_ERROR_STOP=1 -f ops/cleanup/v5.4-test-data-cleanup.sql

# 2. Apply the recommended set, typing back the job count the preview printed:
psql "$DB_URL" -X -v ON_ERROR_STOP=1 \
  -c "set cleanup.groups = 'A,B,C,P'" -c "set cleanup.expect_jobs = '53'" \
  -c "set cleanup.apply = 'yes'" -f ops/cleanup/v5.4-test-data-cleanup.sql

# 3. Optional and separate: the evidence rows, once the docs no longer need them:
#    add -c "set cleanup.include_evidence = 'yes'" and use the new preview count.
```

In the SQL editor, put the same `set ...;` lines above the script text.

Each run is one transaction. If an apply fails, nothing is removed.
